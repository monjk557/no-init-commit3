===============================
Product Requirements Document
Component: collabops-git-ssh
===============================

📌 Purpose
----------
`collabops-git-ssh` is the SSH gateway component in the CollabOps platform that provides Git SSH protocol support. It acts as an SSH server that authenticates users via public key, extracts Git commands, and forwards them to `collabops-git-executor` while preventing shell access.

🧱 Architecture
--------------
Git Client (SSH)
    ↓ (SSH Protocol + Git Commands)
collabops-git-ssh (Port 22/2222)
    ↓ (REST API)
collabops-git-executor
    ↓ (go-git)
Filesystem (/var/lib/git/repos/{owner}/{repo}.git)

🛠️ Technology Stack
-------------------
**Language:** Go 1.21+
**SSH Server:** gliderlabs/ssh or golang.org/x/crypto/ssh
**Authentication:** SSH public key authentication
**HTTP Client:** Standard library with connection pooling
**Database:** Redis/PostgreSQL for key-to-user mapping
**Logging:** Structured logging (logrus or slog)
**Metrics:** Prometheus client
**Configuration:** Viper for YAML config
**Testing:** Standard testing package + testify

🔐 Authentication & Authorization
---------------------------------
1. **SSH Key Authentication:**
   - Accept SSH public key authentication only
   - No password authentication support
   - Map public key fingerprint to user ID
   - Query metadata service or cache for key ownership

2. **Key Management:**
   - Store key-to-user mappings in Redis/PostgreSQL
   - Cache lookups for performance (5-minute TTL)
   - Support key rotation without downtime
   - Log all authentication attempts

3. **User Context:**
   - Extract user ID from key mapping
   - Add `X-USER-ID: <user_id>` header for executor
   - Reject if key not found or disabled

🔁 Git SSH Commands
-------------------
1. **git-upload-pack** (clone/fetch)
   - Command: `git-upload-pack /owner/repo.git`
   - Maps to executor: `/owner/repo/upload-pack`
   - Streams packfile data bidirectionally

2. **git-receive-pack** (push)
   - Command: `git-receive-pack /owner/repo.git`
   - Maps to executor: `/owner/repo/receive-pack`
   - Streams packfile and returns status

3. **Rejected Commands:**
   - Shell access (bash, sh, etc.)
   - SCP/SFTP commands
   - Port forwarding
   - Any non-Git commands

🔧 Core Responsibilities
------------------------
1. **SSH Server Management:**
   - Listen on configured port (22 or 2222)
   - Handle SSH handshake and key exchange
   - Manage concurrent connections

2. **Command Parsing:**
   - Extract Git command from SSH session
   - Parse repository path from command
   - Validate command format and safety

3. **Authentication:**
   - Verify SSH public key
   - Map key to user identity
   - Add authentication headers

4. **Protocol Translation:**
   - Convert SSH streams to HTTP requests
   - Stream data bidirectionally
   - Handle connection lifecycle

🚫 Non-Responsibilities
-----------------------
- No Git protocol parsing or logic
- No direct filesystem access
- No shell access provision
- No repository permission checks
- No REST API endpoint access

📊 Performance Requirements
--------------------------
- Support 1000+ concurrent SSH connections
- Connection pooling to executor
- Stream large packfiles efficiently (>1GB)
- Memory usage: <200MB baseline
- CPU: Moderate (SSH crypto overhead)

🔒 Security Requirements
------------------------
1. **SSH Security:**
   - Support only secure key exchange algorithms
   - Disable weak ciphers and MACs
   - Rate limit connection attempts
   - Fail2ban integration for brute force protection

2. **Command Injection Prevention:**
   - Whitelist allowed Git commands
   - Sanitize all command arguments
   - Prevent shell metacharacter injection
   - Log suspicious command attempts

3. **Access Control:**
   - Verify key ownership before forwarding
   - Add `X-Source: ssh-gateway` header
   - Audit all operations

🔧 Configuration (config.yaml)
------------------------------
```yaml
server:
  port: 2222
  host_key_path: /etc/collabops/ssh_host_key
  max_connections: 1000
  connection_timeout: 30m
  idle_timeout: 5m

executor:
  base_url: http://collabops-git-executor:8080
  timeout: 30m
  max_idle_conns: 100

redis:
  address: redis:6379
  password: ""
  db: 0
  key_prefix: "ssh:keys:"
  ttl: 5m

ssh:
  allowed_key_types:
    - ssh-rsa
    - ssh-ed25519
    - ecdsa-sha2-nistp256
  min_key_bits:
    rsa: 2048
    ecdsa: 256

rate_limit:
  auth_attempts_per_minute: 10
  connections_per_ip: 50

logging:
  level: info
  format: json
  audit_log: /var/log/collabops/ssh-audit.log
```

📐 Example SSH Flow
-------------------
```
1. Client: git clone git@git.collabops.com:alice/project.git
2. SSH: Connection established, key exchange
3. Gateway:
   - Validate client public key
   - Lookup key → user mapping (Redis)
   - Find user_id = "alice"
4. Client: Sends "git-upload-pack 'alice/project.git'"
5. Gateway:
   - Parse command and repo path
   - Add X-USER-ID: alice
   - POST to executor: /alice/project/upload-pack
6. Executor: Stream packfile data
7. Gateway: Forward stream over SSH
8. Client: Repository cloned successfully
```

🔨 Command Examples
-------------------
**Allowed:**
```bash
git-upload-pack 'alice/project.git'
git-receive-pack 'alice/project.git'
git-upload-pack '/alice/project.git'
git upload-pack alice/project.git
```

**Rejected:**
```bash
/bin/bash
scp file.txt server:
ssh server 'ls -la'
git-upload-pack; rm -rf /
```
