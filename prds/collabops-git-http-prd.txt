===============================
Product Requirements Document
Component: collabops-git-http
===============================

📌 Purpose
----------
`collabops-git-http` is the HTTP gateway component in the CollabOps platform that provides Git Smart HTTP protocol support. It acts as a stateless proxy between Git clients and `collabops-git-executor`, handling JWT authentication and HTTP routing while delegating all Git logic to the executor.

🧱 Architecture
--------------
Git Client (HTTP/HTTPS)
    ↓ (Smart HTTP Protocol)
collabops-git-http (Port 8080/443)
    ↓ (REST API)
collabops-git-executor
    ↓ (go-git)
Filesystem (/var/lib/git/repos/{owner}/{repo}.git)

🛠️ Technology Stack
-------------------
**Language:** Go 1.21+
**Framework:** Standard library net/http or Gin/Echo for routing
**Authentication:** JWT (RS256) using golang-jwt/jwt/v5
**HTTP Client:** Standard library with connection pooling
**Logging:** Structured logging (logrus or slog)
**Metrics:** Prometheus client
**Configuration:** Viper for YAML config
**Testing:** Standard testing package + httptest + testify

🔐 Authentication & Authorization
---------------------------------
1. **JWT Validation:**
   - Extract token from `Authorization: Bearer <JWT>` header
   - Validate signature using mounted public key
   - Extract `sub` claim as user ID
   - Add `X-USER-ID: <user_id>` header for executor

2. **Public Key Loading:**
   - Mount via Kubernetes Secret: `/etc/collabops/public.pem`
   - Support hot-reload on key rotation
   - Cache parsed key for performance

3. **Failure Handling:**
   - Missing token: 401 Unauthorized
   - Invalid token: 401 Unauthorized
   - Expired token: 401 Unauthorized
   - Internal errors: 500 Internal Server Error

🔁 Git Smart HTTP Endpoints
---------------------------
Base path: `/repos/{owner}/{repo}.git`

1. **GET /info/refs?service=git-upload-pack**
   - Purpose: Advertise references for clone/fetch
   - Response: Git protocol advertisement
   - Content-Type: application/x-git-upload-pack-advertisement

2. **POST /git-upload-pack**
   - Purpose: Handle clone/fetch operations
   - Request: Git protocol negotiation
   - Response: Packfile stream
   - Content-Type: application/x-git-upload-pack-result

3. **GET /info/refs?service=git-receive-pack**
   - Purpose: Advertise references for push
   - Response: Git protocol advertisement
   - Content-Type: application/x-git-receive-pack-advertisement

4. **POST /git-receive-pack**
   - Purpose: Handle push operations
   - Request: Packfile with references
   - Response: Status report
   - Content-Type: application/x-git-receive-pack-result

🔧 Core Responsibilities
------------------------
1. **Request Routing:**
   - Parse Git Smart HTTP URLs
   - Extract owner/repo from path
   - Map to executor endpoints

2. **Authentication:**
   - Validate JWT tokens
   - Extract and forward user identity
   - Reject unauthenticated requests

3. **Protocol Translation:**
   - Forward Git protocol data unchanged
   - Add required headers (X-USER-ID, X-Source)
   - Stream responses back to client

4. **Request Enhancement:**
   - Add `X-Source: http-gateway` header
   - Add `X-Request-ID` for tracing
   - Forward original client IP

🚫 Non-Responsibilities
-----------------------
- No Git protocol parsing or logic
- No direct filesystem access
- No repository permission checks
- No packfile manipulation
- No REST API endpoint access

📊 Performance Requirements
--------------------------
- Support streaming of large packfiles (>1GB)
- Connection pooling to executor (100+ concurrent)
- Request timeout: 30 minutes (for large clones)
- Memory usage: <100MB baseline
- CPU: Minimal (just proxying)

🔒 Security Requirements
------------------------
1. **Network Security:**
   - TLS termination for HTTPS
   - Rate limiting per user/IP
   - DDoS protection

2. **Input Validation:**
   - Validate URL format
   - Sanitize owner/repo names
   - Limit request body size

3. **Access Control:**
   - Only forward to Git protocol endpoints
   - Block access to executor REST APIs
   - Validate X-Source header on responses

🔧 Configuration (config.yaml)
------------------------------
```yaml
server:
  port: 8080
  read_timeout: 30m
  write_timeout: 30m
  max_header_bytes: 65536

executor:
  base_url: http://collabops-git-executor:8080
  timeout: 30m
  max_idle_conns: 100
  max_conns_per_host: 100

jwt:
  algorithm: RS256
  public_key_path: /etc/collabops/public.pem
  issuer: collabops-orchestrator
  audience: collabops-git

rate_limit:
  requests_per_minute: 100
  burst: 20

logging:
  level: info
  format: json
```

📐 Example Request Flow
-----------------------
```
1. Client: git clone https://git.collabops.com/alice/project.git
2. Git: GET /repos/alice/project.git/info/refs?service=git-upload-pack
3. Gateway:
   - Validate JWT from git credentials
   - Add X-USER-ID: alice
   - Forward to executor: GET /alice/project/info/refs
4. Executor: Returns refs with capabilities
5. Gateway: Stream response to client
6. Git: POST /repos/alice/project.git/git-upload-pack
7. Gateway: Forward with headers
8. Executor: Stream packfile
9. Gateway: Stream to client
10. Client: Repository cloned successfully
```
