# Overview
The CollabOps Git Executor currently provides excellent Git protocol support (Smart HTTP, SSH) and basic read-only REST APIs (diff, tree, blob, commits). However, it lacks server-side Git REST APIs that enable web applications to perform Git operations directly - such as creating commits, editing files, managing branches, and performing complex Git operations through REST endpoints rather than Git protocol.

This creates a significant gap for web-based Git operations:
- **Web file editors** need to create commits without full Git protocol overhead
- **Pull request systems** need to create merge commits programmatically
- **API integrations** need simple REST endpoints for Git operations
- **Browser-based Git clients** need lightweight alternatives to Git protocol

This PRD defines server-side Git REST APIs that complement the existing Git protocol endpoints, enabling direct Git repository manipulation through REST APIs while maintaining security, performance, and Git integrity.

# Core Features

## 1. File Operations API
**What it does**: Direct file creation, modification, and deletion through REST APIs
**Why it's important**: Enables web file editors without Git protocol complexity
**How it works**: REST endpoints that manipulate Git objects directly and create commits

Key endpoints:
- `PUT /repos/{owner}/{repo}/files/{path}` - Create/update single file
- `DELETE /repos/{owner}/{repo}/files/{path}` - Delete single file
- `POST /repos/{owner}/{repo}/commits` - Multi-file operations in single commit

## 2. Commit Management API
**What it does**: Create commits programmatically with full Git metadata
**Why it's important**: Enables complex commit operations for web applications
**How it works**: Accept commit data via JSON, create proper Git commit objects

## 3. Branch and Reference Management
**What it does**: Create, update, delete branches and tags through REST
**Why it's important**: Web-based branch management for PR workflows
**How it works**: Direct Git reference manipulation with validation

## 4. Merge Operations API
**What it does**: Perform Git merges programmatically with conflict resolution
**Why it's important**: Enable pull request merging without Git protocol
**How it works**: Server-side merge operations with conflict detection and resolution

## 5. Repository State API
**What it does**: Query and modify repository state (HEAD, working tree status)
**Why it's important**: Enable advanced Git operations and status checking
**How it works**: Direct repository state inspection and modification

# Technical Architecture

## System Components

### 1. Server-side Git API Layer
**New component within collabops-git-executor**
- REST API handlers for Git write operations
- Leverages existing go-git library and repository access patterns
- Maintains same security model as existing REST APIs (X-Source: orchestrator)
- Integrates with existing permission system

### 2. Git Object Manipulation Engine
**Core Git operations abstraction**
- File tree manipulation (create, update, delete files)
- Commit object creation with proper Git metadata
- Branch and reference management
- Merge operation engine with conflict detection

### 3. Transaction and Conflict Management
**Atomic operation handling**
- Transaction-like semantics for multi-file operations
- Git merge conflict detection and resolution
- Repository locking for concurrent safety (leverage existing locks)
- Rollback mechanisms for failed operations

## Data Models

### Commit Creation Request
```json
{
  "message": "Commit message",
  "author": {"name": "John Doe", "email": "john@example.com"},
  "files": [{"path": "src/main.js", "content": "file content", "action": "create|update|delete"}],
  "branch": "main"
}
```

## APIs and Integrations

- **RESTful URLs**: Follow existing /repos/{owner}/{repo} pattern
- **Permission Service**: Same API as existing (http://api-service.local/permissions)
- **Existing Git Cache**: Leverage existing repository cache and locking
- **Backward Compatibility**: No breaking changes to existing APIs

# Development Roadmap

## Phase 1: Foundation (MVP)
**Scope**: Basic file operations and commit creation
**Goal**: Enable simple web file editing with automatic commits

### Core Components:
1. **File Operations API**
   - PUT /repos/{owner}/{repo}/files/{path} (create/update single file)
   - DELETE /repos/{owner}/{repo}/files/{path} (delete single file)
   - Auto-commit functionality with basic metadata

2. **Enhanced Security Middleware**
   - Input validation for file paths and content
   - Size limits for files and commits
   - Integration with existing permission system

3. **Basic Error Handling**
   - Git-specific error responses
   - Conflict detection (file already modified)
   - Permission error handling

## Phase 2: Multi-file Operations (Extended MVP)
**Scope**: Complex commit operations with multiple files
**Goal**: Enable sophisticated web-based Git operations

### Core Components:
1. **Multi-file Commit API**
   - POST /repos/{owner}/{repo}/commits (multiple file operations)
   - Transaction-like semantics (all or nothing)
   - Custom commit messages and author information

## Phase 3: Branch Management
**Scope**: Branch and reference operations
**Goal**: Complete branch lifecycle management through REST API

### Core Components:
1. **Branch Operations API**
   - POST /repos/{owner}/{repo}/branches (create branches)
   - PATCH /repos/{owner}/{repo}/branches/{branch} (update branch reference)
   - DELETE /repos/{owner}/{repo}/branches/{branch} (delete branches)

## Phase 4: Merge Operations (Advanced)
**Scope**: Automated merge operations with conflict resolution
**Goal**: Enable pull request merging through REST API

### Core Components:
1. **Merge Operations API**
   - POST /repos/{owner}/{repo}/merges (perform merges)
   - GET /repos/{owner}/{repo}/merges/preview (preview merge results)
   - Support for merge, squash, and rebase strategies

## Phase 5: Performance and Monitoring (Production Ready)
**Scope**: Production-ready performance and observability
**Goal**: Scalable, observable, production-grade server-side Git APIs

# Risks and Mitigations

## Technical Challenges

### Risk 1: Git Repository Corruption
**Impact**: High - Could corrupt user repositories
**Mitigation**: Extensive validation, transaction-like operations, comprehensive testing

### Risk 2: Performance Impact on Large Repositories
**Impact**: High - Could slow down entire Git service
**Mitigation**: Streaming for large operations, resource limits, performance monitoring

### Risk 3: Security Vulnerabilities in File Operations
**Impact**: High - Could enable path traversal or unauthorized access
**Mitigation**: Strict input validation, security testing, audit trail

## Technical Specifications

### Error Code Mapping
- 400 Bad Request: Invalid input (malformed JSON, invalid file paths)
- 401 Unauthorized: Missing/invalid authentication
- 403 Forbidden: Permission denied for operation
- 404 Not Found: Repository, branch, or file not found
- 409 Conflict: Git conflicts (branch already exists, merge conflicts)
- 422 Unprocessable Entity: Git validation errors
- 500 Internal Server Error: Git operation failures

This PRD provides a comprehensive foundation for implementing server-side Git REST APIs while maintaining security, performance, and compatibility with the existing CollabOps Git infrastructure.
